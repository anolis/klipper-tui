A Full Klipper Dashboard In Your Terminal

The speed & precision of the CLI.
Built for Klipper 3D Printers.

Run a print, jog the toolhead, watch temperatures, adjust Z offset live, probe the bed, follow the current layer's toolpath and check the camera — over Moonraker, in the terminal, without opening a browser.

$ pipx install klipper-tui

Runs in any terminal. Best in kitty — the webcam and the Klipper mark come through as real images rather than coloured blocks, and frames cost about 2ms each instead of 38.

        Features
        
What it actually does

        

          One websocket to Moonraker, and a terminal. Nothing is installed on the printer.
        

      


      


        

          

            
          

          
Live toolpath, layer by layer

          

            The current layer as the nozzle draws it, read straight from the running file over HTTP range requests. Printed moves are coloured ahead of what is still to come. Zoom, pan, click to centre, or let it follow the print.
          

        


        

          

            
          

          
Braille temperature history

          

            Ten minutes of hotend and bed at four times the vertical resolution of block characters, seeded from Moonraker's temperature store so the graph is already full when you open it.
          

        


        

          

            
          

          
Bed mesh, live while probing

          

            The heightmap fills in point by point as the probe runs — including a run you started in Mainsail, which it joins in progress. Probe count is overridable per run, with a duration estimate as you type.
          

        


        

          

            
          

          
Z offset you can save

          

            Babystep in 0.01mm and 0.05mm while the first layer goes down, then fold the result into the probe's saved offset with one button. It picks Z_OFFSET_APPLY_PROBE or _ENDSTOP based on what your config has.
          

        


        

          

            
          

          
It asks before ruining a print

          

            Homing, jogging, disabling the motors, probing the bed, extruding by hand, running a macro — anything that would wreck a running print asks first, and only while a print is actually running.
          

        


        

          

            
          

          
Speed, flow and motion limits

          

            Feedrate and extrusion percentages with presets and a custom entry, plus velocity, acceleration, square corner velocity and minimum cruise ratio, seeded from the printer's own configuration.
          

        


        

          

            
          

          
Every fan the printer has

          

            Part fan, generic fans and the ones Klipper drives itself, discovered from the printer. Automatic fans are shown with their speed and no controls, because setting them by hand would just be overridden.
          

        


        

          

            
          

          
Your macros, as buttons

          

            Every [gcode_macro] in your config becomes a button, discovered at connect time. Underscore-prefixed helpers stay hidden, and PAUSE, RESUME and CANCEL_PRINT are already the job controls.
          

        


        

          

            
          

          
Console with tab completion

          

            Send G-code and get the printer's replies. Tab completes against the commands your printer actually reports, plus the plain G and M codes; up and down walk back through what you have sent.
          

        


        

          

            
          

          
The camera, in the terminal

          

            kitty is the one to use. It and ghostty get the graphics
            protocol — a real image, and the frame goes out as raw pixels rather than a
            PNG, which is 2ms of encoding instead of 38. Sixel terminals get sixel;
            everything else falls back to half-blocks, which works but looks like it.
          

        


        

          

            
          

          
A dashboard you arrange

          

            Any of the sixteen panels can be on the dashboard or on its own tab. The layout follows the width of the terminal, packing two or three across when there is room and falling back to one column when there is not.
          

        


        

          

            
          

          
Eleven themes, or write your own

          

            Ominous, Mainsail and Forge ship alongside Nord, Gruvbox, Dracula, Tokyo Night, Catppuccin Mocha, Monokai and Solarized. Pick one from Settings, or add your own to the config file.

        Get Started in Seconds
        
Install & Run

        

          Python 3.10 or newer, on Linux or macOS. Nothing is installed on the printer —
          it only needs to be reachable at the address you already type into Mainsail.
        

      


      

        
        

          
1

          
Install via pipx

          
Install in an isolated environment with a global executable:

          

            pipx install klipper-tui
            
          

        


        
        

          
2

          
Launch with Hostname

          
Point klipper-tui to your printer's Moonraker IP or mDNS address:

          

            klipper-tui mainsailos.local
            
          

        


        
        

          
3

          
Or set it once

          

            Put the host in your shell config and run it bare. KLIPPER_PORT,
            KLIPPER_WEBCAM_URL, KLIPPER_RENDER and
            KLIPPER_THEME work the same way.
          

          

            export KLIPPER_HOST=192.168.1.50
klipper-tui
